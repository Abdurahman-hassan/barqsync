# 0.5.2 release

Date: 7 November 2026. Protocol: 11, as 0.5.0 and 0.5.1, which 0.5.2 works with.

## Scope

[PR 43](https://github.com/Abdurahman-hassan/barqsync/pull/43) fixes what the audit of
30 October 2026 (at 0.5.1, commit `475db4c`) found open before a release, and adds the
audit's tests:

- **AU-SEC-01:** a symlink named like a relative partial dir (`.~tmp~` with
  `--delay-updates`, or `--partial-dir=NAME`), from the source tree or a malicious
  server, made the receiver delete a file outside the destination, with exit 0.
- **AU-SEC-07:** the `BARQSYNC_TEST_*` hooks, two of which delete or cut source files,
  are no longer in release builds.
- **AU-COR-02 and AU-COR-03:** on a destination that ignores case or Unicode
  normalization (APFS by default), `--inplace` and `--append*` no longer delete a file
  the source spells differently, and case-only renames converge.
- **AU-COR-01:** a remote delta whose basis is written to during the transfer is refused
  (exit 23) instead of committed wrong with exit 0.
- **AU-COR-05, AU-TST-03, AU-TST-07:** a local copy of a source cut short is an error;
  concurrent runs into one destination tolerate each other's directories and temp files;
  SIGXFSZ is ignored.

Release preparation updates Cargo.toml and Cargo.lock to 0.5.2, dates the changelog, and
updates the README and status notes.

## Verification and publication

The steps are the same as for [0.5.0](0.5.0.md): merge the release preparation, verify CI
on that exact main commit, run `cargo publish --locked --dry-run` in a clean checkout of
it, then create and push the annotated `v0.5.2` tag. The release workflow builds the
macOS and Linux archives, installers and SHA-256 checksums, and creates the GitHub
release. Publishing to crates.io is a manual `cargo publish` from the same checkout.
