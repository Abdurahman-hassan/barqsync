# 0.5.0 release

Date: 28 October 2026. Protocol: 11.

## Scope

Everything merged since 0.4.2:

- [PR 27](https://github.com/Abdurahman-hassan/barqsync/pull/27): hardening against
  hostile peers and source files swapped for symlinks after listing.
- [PR 28](https://github.com/Abdurahman-hassan/barqsync/pull/28) and
  [PR 29](https://github.com/Abdurahman-hassan/barqsync/pull/29): common rsync command
  lines run unchanged (`--no-OPTION`, the `--delete-*` timings, `--max-delete`, filter
  rules, `-m`, `--mkpath`, `--timeout`). Protocol 11.
- [PR 30](https://github.com/Abdurahman-hassan/barqsync/pull/30): `--delete` deletes
  nothing after a file fails to reach the destination.
- [PR 31](https://github.com/Abdurahman-hassan/barqsync/pull/31): `--bwlimit`,
  `--chown`/`--usermap`/`--groupmap` and `--append(-verify)`.
- [PR 32](https://github.com/Abdurahman-hassan/barqsync/pull/32): `--out-format`
  escapes and `--info` flags as rsync has them.
- [PR 33](https://github.com/Abdurahman-hassan/barqsync/pull/33): `-T`,
  `--delay-updates`, `--force`, `--ignore-errors`, the missing-args and symlink-safety
  options.
- [PR 34](https://github.com/Abdurahman-hassan/barqsync/pull/34),
  [PR 36](https://github.com/Abdurahman-hassan/barqsync/pull/36) and
  [PR 38](https://github.com/Abdurahman-hassan/barqsync/pull/38): `-x` leaves destination
  mount points alone with `--delete`, creates source mount points empty in pushes and
  pulls, and follows later sources and `-R` paths as rsync does.
- [PR 35](https://github.com/Abdurahman-hassan/barqsync/pull/35): `--log-file` and
  `--log-file-format`.
- [PR 37](https://github.com/Abdurahman-hassan/barqsync/pull/37): `-E`, `-U` and `-N`.

PRs 31 to 38 were merged in the order 34, 36, 38, 31, 33, 32, 35, 37. Before the first
merge, their combination was rehearsed locally and checked by CI on macOS and Linux,
including the Linux QUIC suite and all-targets Clippy. Each PR was then brought up to date
with main by a merge whose result is exactly the rehearsed tree for that step.

Release preparation updates Cargo.toml and Cargo.lock to 0.5.0, dates the changelog, and
updates the README and status notes. 0.5.x cannot communicate with 0.4.x: upgrade both
ends together.

## Verification and publication

Publication follows [the release procedure](../implementation.md#releasing):

1. Merge the release preparation and verify CI on that exact main commit.
2. In a clean checkout of that commit, inspect `cargo package --list` and run
   `cargo publish --locked --dry-run`.
3. Create the annotated `v0.5.0` tag at that commit and push it. The release workflow
   builds the macOS and Linux archives, installers and SHA-256 checksums, and creates the
   GitHub release.
4. Publish `barqsync` to crates.io from the same checkout.
