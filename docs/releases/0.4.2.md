# 0.4.2 release

Date: 21 October 2026. Protocol: 10. Implementation baseline: `c55abc6`.

## Scope

The release starts from the updated main after 0.4.1 was published. It includes:

- [PR 23](https://github.com/Abdurahman-hassan/barqsync/pull/23): a data stream ending
  or a failed write allows the control stream to deliver the peer's interruption
  notice, preserving exit 20 instead of reporting a connection error.
- [PR 24](https://github.com/Abdurahman-hassan/barqsync/pull/24): QUIC observes a dead
  or dropped SSH connection and bounds cleanup when a peer stops responding.
- The complete-scan deletion barrier and late-interrupt fix already released in
  0.4.1 through [PR 22](https://github.com/Abdurahman-hassan/barqsync/pull/22).

Release preparation updates Cargo.toml and Cargo.lock to 0.4.2, moves the pending
changelog entries into the dated release, and reconciles the README and audit
status notes. No further review findings are implemented in this release task.
Upgrade both machines to receive the shutdown fixes on both ends; the wire
protocol remains 10.

## Verification and publication

The implementation baseline passed [main CI](https://github.com/Abdurahman-hassan/barqsync/actions/runs/39654975389)
on macOS and Linux, including Linux QUIC tests and all-targets Clippy. The release
preparation PR runs the same checks after the version change.

Publication follows [the release procedure](../audit/p1-coordination.md#releasing-next-time):

1. Merge the release preparation and verify CI on that exact main commit.
2. In a clean checkout of that commit, inspect `cargo package --list` and run
   `cargo publish --locked --dry-run`. Confirm the archive contains the intended
   version and source and excludes local notes and unrelated worktrees.
3. Create the annotated `v0.4.2` tag at that commit and push it. The release workflow
   builds macOS and Linux archives, installers and SHA-256 checksums.
4. Publish `barqsync` to crates.io from the same checkout. Verify the registry
   version and checksum, the tag's commit, and the GitHub release assets.

Commits and the tag use the repository owner's identity. Other worktrees and
untracked local notes remain intact. macOS signing/notarization and the other
open findings remain tracked in [remaining.md](../remaining.md).
